# RAG 1단계: 임베딩과 코사인 유사도 이해하기

> 실습 목표: HR 관련 질문과 규정 문장을 숫자 벡터로 바꾸고, 코사인 유사도로 관련성을 비교한다.

## 1. 전체 흐름

**텍스트 → 임베딩 모델 → 숫자 벡터 → 코사인 유사도 계산 → 관련 문서 순위**

이 과정에는 두 가지 작업이 있다.

1. **임베딩 모델**이 텍스트를 숫자 벡터로 변환한다.
2. **코사인 유사도 공식**으로 두 벡터의 방향을 비교한다.

## 2. 텍스트를 벡터로 바꾼다는 뜻

### 쉬운 예시

HR 시스템에 다음 질문이 들어왔다고 가정한다.

- 질문: “남은 휴가가 며칠인지 확인하고 싶어요.”
- 규정: “잔여 연차 일수는 인사시스템에서 조회할 수 있습니다.”

사람은 ‘남은 휴가’와 ‘잔여 연차’, ‘확인’과 ‘조회’가 관련된 표현이라는 것을 알 수 있다.

임베딩 모델은 컴퓨터가 이러한 관련성을 비교할 수 있도록 문장을 숫자 배열로 변환한다.

```text
질문 → [0.12, -0.35, 0.08, ...]
규정 → [0.10, -0.31, 0.09, ...]
```

위 숫자는 원리를 설명하기 위한 예시이며 실제 API 결과가 아니다.

### 정확한 정의

**텍스트 임베딩은 텍스트의 의미적 특징을 수치 벡터로 표현하는 것이다.**

- **벡터:** 여러 숫자로 구성된 배열이다.
- **임베딩 모델:** 텍스트를 벡터로 변환하는 모델이다.
- **임베딩:** 변환 과정 또는 그 결과인 벡터를 뜻한다.

이번 실습의 `text-embedding-3-small`은 기본 설정에서 문장 하나를 **1,536개의 숫자**로 표현한다.

### 오개념 바로잡기

- 임베딩은 **벡터 이미지로 저장하는 것**이 아니다.
- 각 숫자가 ‘휴가 점수’, ‘급여 점수’처럼 명확한 의미 하나씩을 담당하는 것도 아니다.
- 여러 숫자의 조합으로 텍스트의 특징을 표현한다.

## 3. 모델은 어떻게 관련된 표현을 숫자로 바꿀까?

임베딩 모델은 사전 학습 과정에서 언어의 패턴과 관계를 익힌다. 우리가 실습 코드에서 ‘휴가 = 연차’라고 일일이 등록하지 않아도, 학습된 모델을 이용해 관련성을 반영하는 벡터를 얻을 수 있다.

의미 지도 위에 문장의 좌표를 찍는다고 비유할 수 있다. 관련된 의미가 비슷한 위치나 방향으로 표현되도록 학습된 것이다. 다만 이 비유가 모든 문장의 관련성을 완벽하게 구분한다는 뜻은 아니다.

**이번 API 호출은 이미 학습된 모델을 사용하는 추론(inference)이다. 입력 문장으로 모델의 가중치를 새로 학습(training)시키는 작업이 아니다.**

## 4. 코사인 유사도는 무엇일까?

### 쉬운 비유

각 벡터를 원점에서 뻗어나가는 화살표라고 생각한다.

- 두 화살표가 비슷한 방향을 가리키면 코사인 유사도가 높다.
- 방향 차이가 커질수록 코사인 유사도가 낮아진다.

코사인 유사도는 벡터의 길이보다는 **방향의 유사성**을 비교한다.

### 계산 공식

두 벡터 A, B가 있을 때:

$$
\operatorname{cosine\_similarity}(A,B)
=
\frac{A \cdot B}{\|A\|\|B\|}
$$

| 기호 | 의미 |
| --- | --- |
| A · B | 내적: 같은 위치의 숫자를 곱한 뒤 모두 더한 값 |
| ‖A‖ | 벡터 A의 길이, 즉 L2 노름 |
| ‖B‖ | 벡터 B의 길이, 즉 L2 노름 |

벡터 길이가 0이면 이 공식은 정의되지 않는다. 이번 실습은 임베딩 모델에서 받은 0이 아닌 벡터를 비교한다.

## 5. 숫자 두 개로 직접 계산하기

1,536차원 대신 이해하기 쉬운 2차원 예시를 사용한다.

```text
A = [1, 2]
B = [2, 4]
```

B는 A보다 길이가 두 배지만 방향은 같다.

### ① 내적 계산

$$
A \cdot B = 1 \times 2 + 2 \times 4 = 10
$$

### ② 벡터 길이 계산

$$
\|A\| = \sqrt{1^2 + 2^2} = \sqrt{5}
$$

$$
\|B\| = \sqrt{2^2 + 4^2} = \sqrt{20}
$$

### ③ 공식에 대입

$$
\operatorname{cosine\_similarity}(A,B)
=
\frac{10}{\sqrt{5}\times\sqrt{20}}
= 1
$$

**길이는 달라도 방향이 같아서 유사도가 1이다.** 1,536차원에서도 원리는 같다. 곱하고 더할 숫자의 개수가 많아지는 것이다.

## 6. 실습 코드와 연결하기

### 텍스트를 벡터로 변환하는 부분

```python
response = client.embeddings.create(
    model="text-embedding-3-small",
    input=texts,  # 질문과 문서 문장 목록
    encoding_format="float",
)
```

이 부분은 OpenAI API를 호출해 각 문장의 임베딩 벡터를 받는다. API 키는 `OPENAI_API_KEY` 환경변수에서 읽으며 코드에 직접 작성하지 않는다.

### 두 벡터의 유사도를 계산하는 부분

```python
import numpy as np


def cosine_similarity(vector_a, vector_b):
    # 숫자 목록을 NumPy 배열로 변환한다.
    a = np.array(vector_a, dtype=float)
    b = np.array(vector_b, dtype=float)

    # 내적 / (A의 길이 × B의 길이)
    return float(
        np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))
    )
```

| 코드 | 의미 |
| --- | --- |
| `np.dot(a, b)` | 두 벡터의 내적 |
| `np.linalg.norm(a)` | 벡터 A의 길이 |
| `np.linalg.norm(b)` | 벡터 B의 길이 |

**임베딩 생성은 모델이 수행하고, 유사도 계산은 로컬 Python 코드가 수행한다.**

## 7. 왜 벡터 방향으로 의미를 비교할 수 있을까?

코사인 공식 자체가 한국어를 이해하는 것은 아니다. **임베딩 모델이 관련된 의미를 비슷한 방향의 벡터로 표현하도록 학습되어 있기 때문에** 벡터 비교가 의미 검색에 도움이 된다.

따라서 텍스트의 특징을 잘 표현하는 임베딩 모델이 중요하다. 유사도 계산식만으로 검색 품질이 보장되지는 않는다.

## 8. 유사도 점수를 해석할 때 주의할 점

코사인 유사도의 수학적 범위는 **-1부터 1까지**다.

| 값 | 벡터 방향의 관계 |
| --- | --- |
| 1 | 같은 방향 |
| 0 | 서로 직각인 방향 |
| -1 | 정반대 방향 |

텍스트 검색에서는 같은 모델과 설정으로 만든 후보 벡터 사이의 점수를 비교한다.

- `0.8`은 **정답일 확률 80%**라는 뜻이 아니다.
- 점수가 높다고 규정의 사실 여부나 답변 가능성이 보장되는 것은 아니다.
- 낮은 점수나 음수 점수만으로 ‘반대 의미의 문장’이라고 단정할 수 없다.
- ‘몇 점 이상이면 정답’이라는 기준은 실제 데이터로 검증해야 한다.

예를 들어 ‘휴가 신청 방법’과 ‘남은 휴가 조회 방법’은 관련된 주제지만 필요한 답은 다르다. 그래서 높은 점수의 문서가 실제 질문에 답할 수 있는지 확인해야 한다.

## 9. HR·금융 업무시스템 경험과 연결하기

기존 업무시스템에서 제목이나 본문에 검색어가 포함되어 있는지 찾았다면, 임베딩 검색에서는 질문과 문서를 벡터로 바꾸고 의미적으로 가까운 문서를 찾는다.

예를 들어 직원이 ‘남은 휴가 확인’이라고 질문했을 때 ‘잔여 연차 조회’ 규정을 검색하는 데 활용할 수 있다.

다만 임베딩 검색이 항상 키워드 검색보다 우수한 것은 아니다. 사번, 거래 코드, 정확한 규정 번호처럼 일치 여부가 중요한 검색에서는 키워드 검색이 유리할 수 있다.
